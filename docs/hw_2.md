Ветка `hw_2` основана на `hw_1`, исходный SHA: `8e0d6b2262d341aaec5512566a6769a6580c6c64`.
Пока PR #1 открыт, база PR ДЗ №2 — `hw_1`, чтобы ревью показывало только второе задание.
Первый PR можно продолжать менять. Перед следующим ревью ДЗ №2:

```bash
git fetch origin
git switch hw_2
git merge origin/hw_1
```

При конфликте в дизайн-документе сохраняем обновлённые требования ДЗ №1 и заново сверяем
с ними §2.3, особенно метрики, границы пилота и бейзлайн. Разделы до §2.3 этим PR не меняются.
Последний синхронизированный SHA `hw_1` фиксируем в описании PR ДЗ №2.
После слияния #1 переключаем базу второго PR на `main` и проверяем diff.
При squash/rebase-слиянии #1 переносим только коммиты второго задания на новый `main`
через `git rebase --onto origin/main <последний-синхронизированный-SHA-hw_1> hw_2`;
перед переписыванием общей ветки согласовываем это с участниками и используем `--force-with-lease`.
Ветка и история ДЗ №1 этим заданием не изменяются.
