# «Персонажи» в «Интуиции»: ML System Design

Проектирование отдельной фичи **«Персонажи»** для художественных книг в читалке
[«Интуиция»](https://readintuition.ru). Фича помогает вспомнить, кто есть кто, разобраться
в отношениях героев и задать вопрос в чате без спойлеров из непрочитанной части книги.

Это учебный репозиторий курса ITMO ML System Design. Сейчас описаны решение и план пилота;
реализация сервиса запланирована на следующие этапы.

## Задача

В длинной книге легко забыть героя, перепутать его прозвище или потерять нить отношений после
перерыва в чтении. Поиск в интернете может раскрыть дальнейший сюжет, а обычный поиск по книге
не всегда собирает связь, упомянутую в нескольких главах.

В «Интуиции» уже есть чат на основе RAG. Фича «Персонажи» должна дополнить его заранее собранными
сведениями о героях и привязать каждый факт к месту, где о нём узнаёт читатель.

## Возможности фичи

- **Вопросы в чате.** Кто такой герой, кем он приходится другому персонажу, что о нём известно.
  При ответе учитываются история диалога и позиция чтения.
- **Карточка героя.** Имена и прозвища, характеристики, события с его участием и связи с другими
  персонажами. Карточка пополняется по мере чтения.
- **Схема отношений.** Связи между героями, известные к текущему месту книги.
- **Антиспойлер.** В ответах, карточках и схеме используются только сведения из прочитанного.
  Читатель может отключить этот режим, чтобы учитывать всю книгу.
- **Подтверждения.** Факты сопровождаются цитатами и указанием главы; по цитате можно перейти
  к месту в книге. На ошибку можно пожаловаться.

Например, после вопроса «Кто такой Туркин?» читатель может спросить: «А кем Старцев ему
приходится?». Сервис должен понять, о каких героях идёт речь, найти связь в прочитанной части
и ответить с подтверждением. Если ответа в ней ещё нет, сообщить об этом без раскрытия сюжета.

## Как устроено предлагаемое решение

1. **Подготовка книги.** Готовая языковая модель извлекает персонажей, варианты их имён,
   характеристики, факты и отношения. Для каждого сведения сохраняются цитата и позиция в книге.
2. **Хранение.** Собранные данные используются и в чате, и в карточках, и в схеме отношений.
3. **Запрос читателя.** Сервис получает вопрос или выбранного героя, историю диалога, позицию
   чтения и настройку антиспойлера.
4. **Ответ.** Из доступных по позиции данных выбираются нужные сведения, а модель формулирует
   ответ с цитатами. Знания модели о сюжете вне текста книги не должны становиться источником фактов.

**Бейзлайн для сравнения:** текущий подход с обычным RAG, который ищет фрагменты до позиции чтения
и отвечает по ним без заранее собранных связей между героями. Планируемый MVP добавляет
предварительное извлечение и хранение этих сведений.

## Первая итерация и оценка

Пилот запланирован на **двух книгах русской классики**. В него входят автоматическая подготовка
данных, вопросы в чате, карточки, схема отношений и антиспойлер. Используем готовые модели
без дообучения и существующую инфраструктуру «Интуиции».

Качество сравниваем с ручной разметкой героев, связей и характеристик, ответы проверяем
на выборке не менее 100 вопросов по двум книгам. Основные ориентиры пилота:

| Показатель | Цель |
| --- | --- |
| Достоверные ответы | Не менее 95% |
| Ответы со спойлерами | Менее 2% |
| Факты, подтверждённые цитатой | Не менее 80% |
| Время ответа в чате | Не более 5 секунд |

Пороги предварительные и уточняются после замеров бейзлайна. Основные риски: объединение разных
героев, дубли одного героя под разными именами, неверные связи, спойлеры и стоимость длинных книг.

Портреты героев, другие жанры и языки, редактирование карточек читателями и обсуждения
в первую итерацию не входят.

## Документация и структура

Дизайн-документ и схемы находятся в [PR с ДЗ №1](https://github.com/karpaff/intuition-sys-dis/pull/1).
До его слияния файлы разработки доступны в ветке `hw_1`; README размещён отдельно в `main`.

Структура ветки с ДЗ:

```text
docs/
  ml_system_design_doc.md   # Цели, требования, сценарии, метрики и план решения
  img/                     # Схемы бейзлайна и MVP
src/intuition/             # Заготовка для кода следующих этапов
pyproject.toml             # Настройки проекта и Ruff
requirements-dev.txt      # Инструменты разработки
.pre-commit-config.yaml    # Проверки перед коммитом
```

## Настройка окружения

Нужны Git и Python 3.11 или новее. Пока ДЗ №1 открыто, для работы с его файлами переключитесь
на `hw_1`:

```bash
git clone https://github.com/karpaff/intuition-sys-dis.git
cd intuition-sys-dis
git switch hw_1
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
pre-commit install
```

Проверки из корня репозитория:

```bash
ruff check .
ruff format --check .
pre-commit run --all-files
```

Для автоматического форматирования: `ruff format .`.

Каждое ДЗ оформляется отдельной веткой `hw_n` и pull request в `main`.
Работу проверяют ментор и кросс-ревьюеры.
